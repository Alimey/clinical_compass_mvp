# ПсиКомпас · сопровождение между встречами

Ветка `design/experiments`: [актуальные «Правки 2», настройка ИИ и инструкция для Render](docs/revision2.md). Объединённый дневник, расшифровка графиков через внешний ИИ, таблица приёма, видео-заглушки, пошаговые упражнения с автоматическим завершением, простое дерево и исправленная компоновка. [Предыдущий набор изменений](docs/current-changes.md).

Мобильное PWA для психолога/психотерапевта и его пациентов. Основной сценарий: **специалист приглашает пациента → пациент заполняет первичную анкету → карточка создаётся автоматически → встречи, опросы, дневник и переписка связываются с этим специалистом**.

Интерфейс перенесён из командного макета `psicompas (1).html`: синяя палитра, Montserrat, цветущее дерево, мобильные карточки, нижнее меню, светлая и тёмная темы. Все направления макета добавлены, включая кабинет близкого, форум, новости и справочник. [Карта разделов, ограничения подключений и сценарии проверки](docs/mockup-pwa.md).

Оформление обновлено по новому мобильному образцу: мягкие округлые карточки, синяя изогнутая шапка, круговые быстрые действия и иллюстрация специалиста. На компьютере приложение занимает всё окно: боковая навигация, несколько колонок и широкий чат. На планшете и телефоне компоновка перестраивается автоматически; отдельная установка или приложение для компьютера не нужны. [Экран пациента на компьютере](docs/screenshots/desktop-patient.png) · [Экран входа](docs/screenshots/login.png).

Новое: сон и энергия в дневнике, календарь, личные заметки и питание, дневник мыслей, учебные GAD-7 / PHQ-9 / HAM-A, школа пациента и близкого, упражнения с таймерами, игры, план безопасности, соглашение о сопровождении, SOS с удержанием, письма, форум, калькулятор и CSV с разрешёнными агрегатами. Данные сохраняются в SQLite. Доступ близкого и выгрузку контролирует пациент; личные заметки не попадают специалисту.

Данные полностью синтетические. ДЕМО-Альфа / Бета / Гамма — вымышленные варианты, не лекарства. Шкалы представлены в учебном формате. Их медицинская проверка, реальные назначения и маршрутизация требуют отдельной проработки с медкомандой.

## Что работает

| Раздел | Действия |
|---|---|
| Вход | Имя пользователя или телефон + пароль; отдельные роли, сессии и права на сервере |
| Главный экран | У врача — календарь консультаций и список пациентов; у пациента — лента консультаций, дерево по касанию и круговые переходы по разделам |
| Расписание | Свободное время на 14 дней, запись, отмена, завершение прошедшей встречи специалистом; защита от двойного бронирования |
| Карточка | Холдер фото с инициалами, пол, возраст, рост, вес, телефон, первичный контекст, дневник, план, чат |
| Посещения и анализы | Отчёты специалиста, согласованный план после встречи, синтетические результаты с загрузкой текстового документа |
| Опросы | Шаблоны, свой конструктор с разными типами вопросов, копирование шаблона, назначение с дедлайном и повторением, отмена, сохранение ответов |
| Результаты | Специалисту — ответы таблицей и график дневника; пациенту — понятный текст без вымышленного диагноза или клинического балла |
| Таблетница | Подтверждённые специалистом учебные назначения с датами и временем, отметки «принято / пропущено», история и отмена специалистом |
| Общение | Чат, непрочитанные сообщения и отметки прочтения, уведомления и журнал действий |
| Офлайн | По выбору пациента — зашифрованная PIN-кодом копия назначений, записей, посещений и результатов; только просмотр, без чата |
| ИИ | Настоящий запрос к настроенному внешнему API: сводка карточки, вопросы к встрече, генерация редактируемого черновика опроса |
| Telegram | Готовый long-polling бот: приглашение, пошаговая анкета, проверка, автоматическая карточка, одноразовая активация пароля; ИИ-сводка при подключённой модели |
| Push | Настоящие браузерные подписки и Web Push, очередь с повторами, фоновые напоминания об опросах, таблетнице и встречах |

**Для ИИ и Telegram нужны внешние настройки.** Без них формы, расписание, опросы, регистрация по веб-приглашению и остальное локальное приложение работают. Статус «настроено» не равен проверенной доступности внешнего сервиса. Ответов ИИ по заготовке нет. Живая доставка через Telegram, внешний ИИ-провайдер и push на физические устройства здесь ещё не проверены.

## Локальный запуск

Нужен **Python 3.11+**, проверено на 3.12. Node.js нужен только для необязательных проверок JavaScript, сборки интерфейса нет. Существующий Flask/SQLite-проект расширен без перехода на другой стек.

Если репозиторий уже есть: остановите старый сервер, выполните `git fetch origin`, `git switch design/experiments` и `git pull --ff-only origin design/experiments` в папке проекта. Для новой копии:

```bash
git clone --branch design/experiments https://github.com/Alimey/clinical_compass_mvp.git
cd clinical_compass_mvp
python -m venv .venv
```

Windows PowerShell:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.lock
.\.venv\Scripts\python.exe app.py
```

macOS / Linux:

```bash
.venv/bin/python -m pip install -r requirements.lock
.venv/bin/python app.py
```

Откройте `http://127.0.0.1:8000` на компьютере. `python app.py` запускает веб-сервер и фоновые обработчики автоматически. Остановка: Ctrl+C. Не запускайте второй обработчик для той же базы.

Рабочая база по умолчанию — `instance/compass.db`. Новая база получает синтетические сценарии, консультации, шаблоны опросов, пример посещения, анализа и таблетницы. Старая база дополняется новыми таблицами без удаления её записей. Даты встреч в примерах привязаны к моменту первоначального создания базы; уже сохранённые встречи впоследствии не переносятся автоматически.

Чтобы показать свежие сценарии и сохранить старую базу, задайте новый путь до запуска:

```powershell
$env:COMPASS_DB = "instance/showcase-v3.db"
.\.venv\Scripts\python.exe app.py
```

На macOS/Linux: `COMPASS_DB=instance/showcase-v3.db .venv/bin/python app.py`.

Отзыв доступа применяется к следующим запросам сервера. Создание произвольных новых аккаунтов близких пока не предусмотрено.

## Приглашение и автоматическая карточка

1. Специалист: «Пациенты → Пригласить пациента» либо «Ещё → Создать приглашение».
2. Скопируйте одноразовую ссылку (действует 72 часа).
3. Пациент открывает её, указывает вымышленные имя, пол, возраст, рост, вес, телефон, первичный комментарий и пароль.
4. Карточка и аккаунт создаются транзакцией и автоматически закрепляются за пригласившим специалистом. Специалист получает уведомление.

Ввод имени специалиста для привязки заменён уникальным приглашением: так совпадение имён не создаёт неверную связь. Telegram использует ту же привязку. Без подключённого бота веб-регистрация остаётся полноценным работающим путём.

## Опросы, дневник и таблетница

- Карточка пациента → «Опросы»: выберите шаблон, дедлайн и повторение (однократно / ежедневно / раз в 7, 14 или 30 дней).
- «Ещё → Конструктор опросов»: собственные вопросы с оценкой 0–10, да/нет и свободным текстом; можно скопировать шаблон. ИИ создаёт лишь черновик, который специалист проверяет и сохраняет.
- После ответа повторяющийся опрос создаёт следующее задание. После пропущенного дедлайна отвечать всё ещё можно. Отмена задания останавливает эту цепочку; для изменения схемы отмените и назначьте заново.
- «Дневник» доступен пациенту в любой момент, независимо от опросов. Это и есть **самоотчёт**: собственные записи о настроении, тревоге и самочувствии.
- В «План и варианты → Управлять назначениями» специалист подтверждает синтетическое расписание таблетницы. Пациент не может сам менять назначения.
- Время консультаций и таблетницы — **Москва, UTC+3**. Дедлайны в форме `datetime-local` вводятся во времени устройства, затем сохраняются в UTC. Другие даты отображаются в часовом поясе устройства.
- «Принято / пропущено» — самоотметки пациента, не подтверждение фактического приёма. Будущие приёмы отмечать нельзя; исправлять прошлые можно в пределах 30 дней.

## Настоящий внешний ИИ API

1. Скопируйте `.env.example` в `.env`, если `.env` ещё не существует. Не перезаписывайте свои настройки. Файл `.env` исключён из Git.
2. Заполните локально:

```dotenv
COMPASS_AI_BASE_URL=
COMPASS_AI_MODEL=
COMPASS_AI_API_KEY=
```

Используйте OpenAI-совместимый API. `BASE_URL` — базовый адрес провайдера, например `https://api.openai.com/v1`, **без** `/chat/completions`; модель — реально доступный вам идентификатор из документации провайдера. Ключ вводите только в локальный `.env`, не в чат и не в Git. Для внешнего сервиса используется HTTPS; HTTP разрешён лишь для локального тестового API.

3. Перезапустите приложение. Карточка пациента → «ИИ-помощник»; для опросов — «Конструктор → Составить с ИИ».

В запрос уходят синтетический контекст, последние записи и вопрос, без необходимости передавать телефон. Ответ сохраняется отдельно как ИИ-черновик, не изменяет диагноз/план и не создаёт назначений. Ошибки доступа или модели показываются явно. Автоматических действий по ответам модели нет.

Если генерация опроса возвращает неподходящий формат, шаблон не сохраняется. До подключения API можно вручную создавать и копировать опросы — это отдельная рабочая функция, а не имитация ИИ.

## Telegram-бот

Бота ещё нужно создать через **BotFather**. В локальном `.env` задайте:

```dotenv
COMPASS_TELEGRAM_BOT_TOKEN=
COMPASS_TELEGRAM_BOT_USERNAME=
COMPASS_PUBLIC_URL=
```

`USERNAME` — без `@`. `PUBLIC_URL` — адрес приложения, который пациент действительно может открыть. Для телефона в вашей Wi-Fi сети это может быть `http://IP-КОМПЬЮТЕРА:8000`; `localhost` на телефоне означает сам телефон. Для пациентов вне вашей сети понадобится доступный HTTPS-сервер.

После перезапуска специалист создаёт приглашение и получает также персональную ссылку Telegram. Бот собирает анкету, просит проверить данные и подтвердить создание карточки. При настроенном ИИ API добавляет нейтральную ИИ-сводку для проверки, не меняя исходные ответы. Пароль в Telegram не запрашивается: пациент задаёт его через одноразовую ссылку активации (24 часа).

Используется long polling: публичный Telegram-webhook и туннель на локальный компьютер не нужны. Повторные обновления Telegram не дублируют аккаунт. Исходящие сообщения хранятся в очереди с ограниченными повторами. История Telegram не синхронизируется с чатом специалиста: бот предназначен для первичной анкеты.

## Push, напоминания и эскалация

- Внутренние уведомления и чат опрашиваются каждые 5 секунд в видимой вкладке. Обзор и список пациентов обновляются при новых событиях, если пользователь не редактирует поле. Чат обновляет только ленту и не стирает черновик.
- «Ещё → Подключить push в браузере» запрашивает разрешение и сохраняет действительную подписку. Нужны поддерживаемый браузер, HTTPS или localhost; на iPhone — установленная PWA с поддержкой push.
- Ключ VAPID автоматически создаётся в каталоге рабочей базы (`push-vapid.pem`, закрытый ключ не передаётся в браузер). При размещении укажите контакт администратора `COMPASS_PUSH_CONTACT`.
- Фоновый обработчик создаёт напоминания об опросах/дедлайнах, таблетнице и встречах. Он запущен при `python app.py`; сетевые операции Telegram/ИИ и push выполняются отдельно от планировщика.
- Web Push использует настоящую зашифрованную отправку. Очередь повторяет временные ошибки с задержкой; при недействительной подписке она отключается. Семантика доставки — с возможным повтором после сбоя, не «строго один раз»; одинаковый `tag` заменяет повторное уведомление на устройстве.
- Текст push нейтральный, без самочувствия и других деталей. Передача push-сервису не равна просмотру врачом.
- Через `COMPASS_ESCALATION_MINUTES` (по умолчанию 15) непросмотренный сигнал ставится во **внутреннюю очередь эскалации**, видимую в «Ещё». После просмотра сигнала она помечается разрешённой. Внешний протокол и адресат организации не определены: отправка в медорганизацию не имитируется.

Push зависит от браузера, ОС, сети и внешнего сервиса. Гарантии экстренной доставки и SMS нет. По возможности проверьте конкретные телефоны до показа.

## Офлайн-доступ

Пациент: «Ещё → Мои согласия → Назначения и записи без интернета», задайте PIN из 6 цифр и сохраните копию. В IndexedDB записываются только соль, IV и шифротекст AES-GCM; ключ выводится из PIN через PBKDF2 и не сохраняется. Чат, ключ внешнего API, пароль и токен сессии в копию не попадают.

После перезагрузки без сети на экране входа появится «Открыть офлайн-копию». Можно посмотреть назначения, записи, отчёты о посещениях и результаты; отправить данные или общаться нельзя. Есть дата сохранения: копия может устареть. Во время текущего входа копия обновляется при загрузке данных; после перезагрузки для обновления сохраните её заново с PIN. Выход и кнопка удаления стирают копию.

Это защита демонстрационных данных, не заявление о безопасности медицинских персональных данных: короткий PIN допускает перебор, устройства могут быть общими. API-ответы в service worker не кэшируются; он хранит только оболочку интерфейса.

## Телефон в одной сети

Windows PowerShell:

```powershell
$env:COMPASS_HOST = "0.0.0.0"
.\.venv\Scripts\python.exe app.py
```

macOS/Linux: `COMPASS_HOST=0.0.0.0 .venv/bin/python app.py`.

Оба устройства — в одной Wi-Fi сети. Узнайте IPv4 компьютера (`ipconfig` на Windows) и откройте на телефоне `http://IP-КОМПЬЮТЕРА:8000`. При необходимости разрешите TCP 8000 в брандмауэре частной сети. Компьютер должен оставаться включённым.

По локальному HTTP работают интерфейс и формы. Установка PWA, Web Crypto для офлайн-копии и push на телефоне требуют HTTPS; исключение localhost относится к самому устройству. PWA-установка пока остаётся дополнительной возможностью, не обязательным условием демонстрации.

## Размещение

На Linux с Gunicorn и одним фоновым обработчиком:

```bash
COMPASS_SECURE_COOKIES=1 .venv/bin/gunicorn --config python:compass.gunicorn_conf --bind 0.0.0.0:8000 --workers 1 --threads 4 'app:create_app()'
```

За HTTPS reverse proxy сохраняйте исходный `Host`. `COMPASS_SECURE_COOKIES=1` используется только с HTTPS. Постоянный диск обязателен для SQLite, VAPID-ключа и восстановления данных. Один экземпляр приложения / один worker на базу; горизонтальный кластер не реализован.

```bash
docker build -t clinical-compass .
docker run --rm -p 8000:8000 -v compass-data:/data --env-file .env clinical-compass
```

Можно опустить `--env-file`, если подключения не нужны. Docker запускается не от root. Для корпоративного HTTPS-прокси передавайте стандартные proxy build args и доверенный CA-bundle через `--secret id=build_ca,src=/путь/к/ca-bundle.crt`; TLS-проверка не отключается. Если сертификат нужен внешним вызовам в runtime, подключите доверенный bundle средствами ОС / стандартных переменных SSL_CERT_FILE и REQUESTS_CA_BUNDLE, не отключайте проверку сертификатов.

GitHub Pages не запускает Python API. Публичный сервер и размещение в магазинах автоматически не создаются. **Сервер** — программа/компьютер, обрабатывающий запросы; **облако** — вариант размещения этого сервера у провайдера. При локальном запуске сервером является ваш компьютер.

## Сценарий показа на 3 минуты

1. **0:00–0:35:** вход, лента консультаций, карточка с основными данными, посещением и анализом.
2. **0:35–1:15:** назначить короткий опрос; во втором окне пациент отвечает и отмечает таблетницу.
3. **1:15–1:50:** специалист видит ответы, обсуждает их с пациентом в чате; показать непрочитанное/прочтение.
4. **1:50–2:30:** при заранее подключённом API запросить короткую ИИ-сводку; проверить и обсудить, не меняя план автоматически. Без API этот пункт нельзя выдавать за работающий ИИ.
5. **2:30–3:00:** показать запись на приём или регистрацию по приглашению; офлайн-копию оставить для вопросов.

Четыре технических сценария для подготовки: первичная регистрация, регулярное наблюдение, сигнал безопасности с проверкой специалистом, офлайн-доступ. Медицина и протоколы эскалации требуют отдельной проверки вашей медкомандой. При непосредственной опасности нужна экстренная помощь, а не ожидание ответа в приложении.
