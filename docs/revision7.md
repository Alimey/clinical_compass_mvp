# «Правки 7» — регистрация, экран входа и подготовка демонстрации

Ветка `design/experiments`.

## Что изменено

- На экране входа появилась кнопка смены светлой и тёмной темы. Она также доступна при регистрации и открытии приглашения. Выбор сохраняется на устройстве и действует после авторизации.
- Дерево увеличено: 180–200 px на телефоне, до 380 px на компьютере. Цитаты получили более крупный курсивный шрифт с засечками и центрирование; кнопка «Другая мысль» сохранена.
- Добавлены кнопки «Создать аккаунт» и «Есть приглашение?», выбор роли, проверка совпадения паролей и сообщения об ошибках без очистки введённых полей.
- Специалист указывает имя, телефон, пароль, специализацию и при желании организацию. Создаётся отдельный пустой кабинет без доступа к чужим пациентам; на главной предлагается пригласить первого пациента.
- Пациент открывает приглашение специалиста или вставляет ссылку/код через экран регистрации. Прежняя первичная анкета и автоматическая привязка карточки сохранены.
- В «Моих согласиях» пациент может создать приглашение близкого. Ссылка действует 72 часа и используется один раз. Близкий создаёт свой аккаунт и пароль. Привязка берётся только из приглашения.
- Регистрация близкого не включает разрешения. Пациент отдельно разрешает получать SOS и дополнительные сведения, а затем может отозвать доступ. Эти настройки действуют для всех связанных с ним близких. Дневник и переписка близкому не открываются.

Номер телефона используется как логин. Проверка SMS и квалификации специалиста в этом прототипе не подключены. Существующие аккаунты и данные сохранены; добавляется таблица приглашений близкого. Пароли хранятся в виде хешей.

## База данных простыми словами

**База уже подключена. Для локального показа ничего дополнительно устанавливать не нужно.** Приложение автоматически создаёт SQLite — файл `instance/compass.db`. В нём находятся пользователи, связи между ними, дневники, сообщения, назначения и остальные записи. После перезапуска на том же диске они остаются.

Для одного демонстрационного сервера SQLite достаточно. PostgreSQL — отдельный сервер базы данных; он может понадобиться позже для нескольких экземпляров приложения и более высокой нагрузки. Простое добавление адреса PostgreSQL в настройки сейчас не переключит SQLite на него: понадобится адаптация кода.

На Render нужно различать работу приложения и сохранность файла базы. Бесплатный сервис с временным диском может терять изменения после перезапуска или нового развёртывания. Для постоянного сохранения SQLite:

1. Если текущие записи важны, сначала сделать резервную копию и сохранить её вне сервиса. Не менять путь базы до копирования: новый путь создаст новую базу с начальными примерами.
2. Выбрать тариф сервиса с поддержкой постоянного диска. В настройках Render открыть **Disks → Add Disk**, указать точку монтирования `/var/data`.
3. В **Environment** задать `COMPASS_DB=/var/data/compass.db`.
4. Развернуть приложение. При первом запуске новая база создастся автоматически. Для сохранения прежних записей на постоянный диск нужно перенести резервную копию и направить приложение на неё.

Для локальной резервной копии из папки проекта:

```bash
python -m compass.backup --database instance/compass.db --output instance/backups/before-demo.db
```

Команду выполняют тем Python, которым запущен проект. На Render база находится на сервере; локальная копия проекта не скачивает серверные записи автоматически. Текущий файл базы конкретного Render-сервиса в рамках этих правок не переносился.

## Готовые аккаунты для съёмки

Они уже создаются в новой демонстрационной базе и связаны между собой:

| Роль | Логин | Профиль |
|---|---|---|
| Врач | `doctor` | Анна Соколова |
| Пациент | `patient-a` | Александра Морозова, пациент Анны |
| Близкий | `relative` | Екатерина Морозова, сестра Александры |

Пароль для всех трёх: `compass-demo`. Быстрые кнопки на входе открывают эти же аккаунты. Создавать ещё три для записи не обязательно; собственные аккаунты теперь тоже можно зарегистрировать.

Открыть приложение в трёх отдельных профилях браузера или разных браузерах. Например: врач — Chrome, пациент — Edge, близкий — Firefox. Обычные вкладки одного профиля используют общий вход и не подходят для одновременных ролей. Все окна должны открывать один и тот же адрес приложения.

## Как записать демонстрацию

Для первой записи удобнее компьютер. Установить OBS Studio, добавить источник «Захват окна» с браузером, включить микрофон при необходимости и нажать «Начать запись». Если нужно показывать несколько браузеров с переключением между ними, использовать «Захват экрана». Перед записью отключить личные уведомления и закрыть лишние окна. Для проверки мобильной версии можно отдельно записать экран телефона с установленной PWA.

Предлагаемый сценарий на 3 минуты:

| Время | Действие |
|---|---|
| 0:00–0:25 | Показать вход, смену темы, дерево и три роли. Войти как Александра. |
| 0:25–0:55 | На главной показать ближайший приём и таблетницу. Открыть дневник, заполнить самочувствие и отправить запись. |
| 0:55–1:30 | Переключиться к Анне. Показать новое уведомление, отметить его прочитанным; открыть Александру через «Пациенты» и посмотреть новую запись. |
| 1:30–2:00 | В чате пациента написать «Хочу обсудить сон на следующей встрече». В кабинете врача ответить и показать появление ответа у пациента. |
| 2:00–2:30 | Пройти назначенный пациенту опрос и показать результат у врача. Проверить заранее, что в базе есть незавершённый опрос; при необходимости врач назначает новый до записи. |
| 2:30–3:00 | Показать кабинет близкого и настройки согласий пациента. Завершить демонстрацией удобной навигации и главной страницы. |

Если нужен именно показ нового пользователя, записать отдельный короткий ролик: «Создать аккаунт → Специалист → Пригласить пациента», открыть ссылку во втором браузере, заполнить анкету и показать появление карточки у врача. Затем пациент создаёт приглашение близкого в «Моих согласиях».

Можно попросить коллег сыграть врача и пациента: они будут пользоваться работающими аккаунтами с вымышленными сведениями. Для демонстрации ИИ предварительно нужен настроенный внешний API; остальные шаги сценария от него не зависят.

## Проверки и обновление

Добавлены серверные проверки регистрации: независимый кабинет врача, сохранение после перезапуска, уникальность телефонов, хеширование паролей, привязка близкого, срок и одноразовость приглашений, разделение ролей и отзыв согласия. Браузерная проверка проходит путь регистрации трёх ролей в независимых сессиях и проверяет тему и компоновку на ширинах 320–1440 px.

На Render: ветка `design/experiments` → **Manual Deploy → Deploy latest commit** → дождаться **Live** → обновить страницу. PWA-оболочка — `compass-shell-v15`. Для новых форм регистрации внешние API и Telegram не нужны.
