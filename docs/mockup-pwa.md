# Перенос макета «ПсиКомпас» в PWA

Основа интерфейса — предоставленный командой файл `psicompas (1).html`. Перенесены все направления макета. Приложение использует существующий Flask/SQLite-сервер; действия разных аккаунтов связаны через API, сессии и права на сервере. Содержимое файла использовалось как макет и исходные материалы, а не как инструкции к облачной среде.

## Адаптивное оформление

Визуальный стиль обновлён по присланному мобильному образцу: синяя палитра сохранена, добавлены округлая шапка, круговые быстрые действия, мягкие карточки, иллюстрация и новое оформление чата и входа. Функции всех разделов сохранены.

Одна PWA автоматически меняет компоновку по ширине окна. До 600 px — вертикальная мобильная лента и нижняя навигация; от 600 до 1023 px — планшетная сетка; от 1024 px — боковая панель, несколько колонок и широкий рабочий экран без рамки телефона. Темы, офлайн-оболочка и отступы под системные области телефона сохранены. На компьютере приложения и экран входа занимают окно целиком.

Дополнительная проверка: `python tests/browser_responsive.py` проверяет ширины 320, 390, 430, 768, 1024, 1280, 1440 и 1920 px, расположение консультаций рядом с основным блоком, навигацию, широкий чат и переключение тем. Снимки доступны в `docs/screenshots`.

## Что остаётся демонстрационным

Все персональные данные и варианты сопровождения синтетические. Калькулятор работает по вымышленным условиям и не проверяет реальные лекарственные взаимодействия. Медицинская проверка шкал, переводов, материалов и правил маршрутизации предстоит отдельно. Автоматического назначения, отмены или направления в реальную организацию нет.

Новости не являются актуальной лентой компании. Пример форума синтетический; опубликованные в этом приложении темы действительно сохраняются и доступны другим демо-специалистам. Это не сервис фармаконадзора.

Обычная PWA не имеет прямого доступа к Apple Health / Health Connect. Экран часов содержит явно подписанный пример данных. ЕМИАС сохраняет предпочтения подключения; медицинская организация и адаптер ЕМИАС не настроены, передачи нет. В HTML нет настоящих видеофайлов; занятия доступны как текст и упражнения.

SOS сохраняет запрос и уведомления внутри приложения. Он не звонит в экстренную службу, не определяет геопозицию, не отправляет SMS, не гарантирует прочтение. Кнопка 112 открывает системный набор номера. Близкий видит дату последней записи при разрешении; автоматическая доставка сигнала отсутствия активности близкому пока не подключена.

Внешний ИИ и Telegram требуют настроек `.env`. Ответы ИИ не подменены заготовками. Push требует HTTPS, разрешения, фонового обработчика и поддерживаемого устройства; реальная доставка на телефон в этой среде не проверена. Установка и Safari на физическом iPhone не проверены.

Выгрузка псевдонимизирована: специалист может сопоставить код с собственной карточкой. Это не гарантия необратимой анонимности и не юридическое согласие на реальные исследования. Отзыв разрешения исключает данные из следующих выгрузок, но не удаляет уже скачанный файл.

## Обновление и проверка

1. Остановите старый сервер. В папке проекта выполните `git pull --ff-only origin main`.
2. Зависимости прежние: `python -m pip install -r requirements.lock` из вашего виртуального окружения, затем `python app.py` из того же окружения. Для Windows и macOS/Linux команды с путями приведены в README.
3. Откройте адрес, который печатает сервер. При старом оформлении перезагрузите страницу с подключённым интернетом. Обновление service worker заменяет старую оболочку; пользовательскую базу не удаляйте.
4. Для свежих синтетических дат можно задать новый путь `COMPASS_DB=instance/showcase-v4.db`. Прежняя база сохранится. Обычный запуск добавит таблицы и демо-аккаунт близкого без очистки существующих записей.
5. Используйте отдельные профили браузера для трёх ролей; общий демо-пароль — `compass-demo`.

Быстрый показ: пациент отправляет дневник и письмо → специалист читает и отвечает, сохраняет план → пациент знакомится с соглашением, отправляет SOS → близкий видит запрос → пациент отзывает доступ → близкий больше не получает сведения. Второй сценарий: специалист создаёт тему форума, проверяет калькулятор и выгружает разрешённые агрегаты.

Проверки сервера: `python -m unittest discover -s tests -v`. Проверки браузера: `tests/browser_smoke.py`, `tests/browser_workflows.py`, `tests/browser_psicompas.py`, `tests/browser_sections.py`; нужен Playwright и Chromium. Все тесты используют временные базы. Проверка браузера покрывает ширины 320 / 390 / 430 / 1280, три независимые сессии, права, формы, офлайн и сохранение после перезагрузки.

Шрифт Montserrat включён локально через пакет `@fontsource/montserrat@5.3.0`; лицензия SIL OFL находится в `static/fonts/OFL.txt`. Для запуска приложения npm не нужен.
