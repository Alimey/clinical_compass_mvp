# Напоминания и отсутствие пациента

Публичный адрес Render использует HTTPS (TLS). Браузер обращается к API по HTTP-запросам с JSON; открытая страница проверяет новые уведомления каждые 5 секунд. При локальном запуске по `http://localhost:8000` соединение HTTP. WebSocket в текущем приложении не используется.

Системные уведомления доставляются через Web Push: браузер создаёт подписку, сервер отправляет зашифрованное сообщение push-службе браузера, service worker показывает его на устройстве. SMS и обычные мобильные звонки в эту доставку не входят.

## Когда создаются уведомления

| Событие | Получатель и условие |
|---|---|
| В таблетнице нет отметки «Принято» | Пациент, через 30 минут после назначенного времени. Уведомление не утверждает, что человек действительно не принял лекарство. Отметка «Пропущено» тоже учитывается как отсутствие приёма; указаний принять двойную дозу нет |
| Опрос ожидает выполнения | Пациент, в течение суток перед сроком и однократно после его истечения; врач получает уведомление о просрочке |
| Назначенная шкала или упражнение не выполнены | Те же условия. Методики, проводимые на приёме по лицензии, исключены из онлайн-напоминаний |
| Пациент не открывает приложение 3 суток | Его врач; связанный близкий — только при разрешённых сигналах и согласии на уведомления об отсутствии |

Повторные проходы планировщика не создают дубликаты одного события. Отсутствие — один эпизод: после возвращения пациента отсчёт начинается заново. Время посещения отдельно от дневника. Видимая страница отправляет отметку не чаще раза в минуту; скрытая вкладка и вкладка без действий более пяти минут не поддерживают активность бесконечно. Новый вход и возвращение к странице учитываются снова.

У старых пациентов отсчёт отсутствия начинается с установки обновления, а не с давно записанного дневника. У новых — с создания аккаунта. В уведомлении врачу не делается вывод об ухудшении состояния.

Перед отправкой push повторно проверяется, что задание ещё не выполнено или отменено, приём не отмечен и согласие близкому действует. Устаревшие напоминания снимаются с очереди и скрываются в списке. Уже переданный внешней push-службе пакет отозвать невозможно. На экране блокировки нет имени пациента, названия препарата, результатов или содержания сигнала — только предложение открыть ПсиКомпас.

## Как включить

1. Обновить ветку `design/experiments` на Render. Команда запуска:

   ```text
   gunicorn --config python:compass.gunicorn_conf --bind 0.0.0.0:$PORT --workers 1 --threads 4 'app:create_app()'
   ```

   В корне проекта также добавлен стандартный `gunicorn.conf.py`: команда `gunicorn 'app:create_app()'` подхватывает планировщик без дополнительного аргумента. Старая команда `gunicorn app:app` к текущей фабрике приложения не подходит. Не задавать `COMPASS_DISABLE_WORKER=1` на рабочем сервисе.

2. В Render → Environment задать реальный контакт администратора, например `COMPASS_PUSH_CONTACT=mailto:your-address@example.com`. Это публичный контакт отправителя, не пароль. Для HTTPS используется `COMPASS_SECURE_COOKIES=1`.
3. Использовать постоянно работающий сервер. Бесплатный Render может засыпать без посещений; во сне фоновые проверки не выполняются и своевременная доставка не обеспечивается. Хранить SQLite и расположенный рядом `push-vapid.pem` на постоянном диске, чтобы не терять подписки и ключ при развёртывании.
4. На каждом телефоне и компьютере войти под нужной ролью → **Настройки → Подключить push** → разрешить уведомления браузеру. На iPhone сначала установить PWA через Safari → «Поделиться» → «На экран Домой», затем открыть её и разрешить push. Поддержка зависит от версии ОС и браузера.
5. Нажать **«Проверить уведомление»**, свернуть приложение и проверить системное сообщение. Тест отправляется на подключённые устройства текущего аккаунта. Если подписок нет, показывается ошибка, а не ложное сообщение об успешной доставке.
6. Пациенту открыть **Мои согласия**: разрешить близкому получать сигналы и включить **«Сообщать близкому о длительном отсутствии»**. Близкий должен быть зарегистрирован по приглашению и отдельно разрешить push на своём устройстве.

## Настройки и проверки

```text
COMPASS_INACTIVITY_HOURS=72
COMPASS_MEDICATION_GRACE_MINUTES=30
```

Эти значения используются по умолчанию и добавлены в `.env.example`. При отсутствии приложения больше трёх суток не нужно ждать нового входа пациента: уведомление создаёт серверный планировщик, если сервер работает.

Проверены серверные события и однократность, повторный эпизод после возвращения, отмена очереди после выполнения или отзыва согласия, отсутствие медицинских сведений в push-пакете и доступ по ролям. Отправка push-службе проверена с подменой сетевого транспорта; реальная доставка на физический телефон или компьютер из этой среды не проверялась. Для неё предусмотрена тестовая кнопка.

Браузерная проверка охватывает видимость и простой вкладки, время посещения, согласия и настройки пациента и близкого. Отдельная проверка запускает Gunicorn и подтверждает работу фонового планировщика. PWA-оболочка — `compass-shell-v20`; существующая база дополняется автоматически.
