# Замеры для постера

## Windows: один запуск и отчёт в браузере

Если приложение уже работает из `.venv`, обновите ветку `design/experiments` и откройте в папке проекта **`run-local-tests.cmd`**. Можно запустить из PowerShell:

```powershell
git fetch origin
git switch design/experiments
git pull --ff-only origin design/experiments
.\run-local-tests.cmd
```

Файл установит дополнительные инструменты из `requirements-local.txt`, один раз скачает Chromium для автоматизации браузера и выполнит три этапа:

1. API, нагрузка 1/5/10/25/50 сессий в двух прогонах и восстановление после остановки процесса.
2. Открытие экрана входа и сохранение дневника на ширине 390/1440 px, 20 удержаний SOS с проверкой уведомлений врача и разрешённого близкого.
3. Серверные функциональные тесты.

Обычно это занимает 5–10 минут после установки зависимостей. Окно показывает ход выполнения. Отчёт `report.html` откроется в браузере; он и исходные JSON/CSV/журналы сохраняются в новой папке **`test-results/local-ДАТА_ВРЕМЯ/`**. Для PDF: Ctrl+P → «Сохранить как PDF». При ошибке окно останется открытым: сохраните последние строки ошибки.

Используется отдельная временная база и свободный локальный порт. Рабочая база не изменяется. Windows-сервер — **Waitress, один процесс и четыре потока**; это отличается от Gunicorn на Render и в исходном облачном замере. Отчёт показывает текущую ОС, Python и сервер. Все цифры относятся к тому компьютеру, где запускаются тесты.

Набор из 13 основных браузерных серий этим способом не запускается: часть этих сценариев привязана к Linux. Выполняются специальный браузерный замер и серверные тесты; отчёт не приписывает им результаты остальных проверок. Установка PWA и системные push на реальных телефонах не проверяются.

Ручной эквивалент без `.cmd`:

```powershell
.\.venv\Scripts\python.exe -m pip install -r tests\measurements\requirements-local.txt
.\.venv\Scripts\python.exe -m playwright install chromium
.\.venv\Scripts\python.exe -X utf8 tests\measurements\run_local.py
```

`run_local.py` также работает на macOS/Linux с Gunicorn. Параметр `--no-open` отключает автоматическое открытие отчёта; `--output ПУТЬ` выбирает новую или пустую папку. Существующие результаты не перезаписываются. `COMPASS_TEST_SERVER=waitress` позволяет явно выбрать Waitress для отдельного сравнительного замера.

Полный процесс через Waitress проверен в Linux: нагрузка, специальный браузерный замер, 20 SOS, все 87 серверных тестов и сборка отчёта. Выполнение на физической Windows ещё требует подтверждения. Во время замера не запускайте другие тесты и тяжёлые программы.

## Исходный Linux-прогон и PDF для постера

Скрипты запускают копию приложения с временной SQLite-базой. Они не обращаются к рабочему Render и не требуют внешних ключей. Выполняйте их последовательно: одновременный запуск искажает задержки.

Из корня проекта с настроенной `.venv`:

```bash
.venv/bin/python tests/measurements/run_benchmarks.py
python tests/measurements/run_ui_metrics.py
python tests/measurements/run_validation.py
python tests/measurements/build_report.py
```

Для трёх последних команд используйте Python с `playwright`, `matplotlib`, `reportlab` и установленным системным Chromium. Браузерные проверки запускают сервер через `.venv/bin/python`. Дополнительные пакеты нужны только для тестирования и отчёта.

Результаты сохраняются в `test-results/metrics/`, который исключён из Git. Можно задать `COMPASS_METRICS_OUT` и `COMPASS_REPO`. На протяжении одного замера не меняйте коммит проекта: сборщик проверяет совпадение версий.

- `run_benchmarks.py`: API без нагрузки, две серии с 1/5/10/25/50 активными сессиями, неверные входные данные, рост списка пациентов, аварийный перезапуск и восстановление снимка.
- `run_ui_metrics.py`: открытие экрана входа и сохранение дневника при ширине 390/1440 px; 20 реальных удержаний SOS с независимыми случайными отправками; уведомления в открытых панелях врача и разрешённого близкого. Системные push не измеряет.
- `run_validation.py`: серверные тесты, все `browser_*.py`, запуск Gunicorn и синтаксис JavaScript. Серии идут по очереди.
- `build_report.py`: PDF-отчёт, текст для постера, изображения и PDF графиков, исходные CSV и архив. Метрики берутся из JSON предыдущих запусков.

`build_report.py` сохраняет оформление и описание исходного стендового сеанса 26.10.2026; для замеров на своём компьютере используйте `run_local.py` и его отчёт с актуальной конфигурацией.

Время ответа API, готовность экрана и доставка системного push — разные показатели. Нагрузка 50 сессий означает максимальную проверенную ступень, а не установленный предел. Короткий прогон без ошибок не доказывает непрерывную доступность. Локальные цифры нельзя приписывать Render без отдельного измерения на сервере с сопоставимой конфигурацией.
